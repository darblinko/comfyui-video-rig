comfyui-video-rig

Scripts that run ComfyUI on a single-GPU EC2 instance reached only through SSM, submit image and video jobs to it, and stop it when it goes idle. For comparing open image-to-video models on the same prompt and seed without leaving a GPU instance running.

Problem

A 5 s, 720x1280 image-to-video clip took between 1,378.9 s and 1,587.9 s on the recorded runs, measured from queueing to the last download. The two-model bake-off took 3,078.3 s (51.3 minutes) for one prompt on that measure; GPU time itself was not recorded. A GPU instance left running after a session, or held by a hung job, bills until someone notices.

ComfyUI has no authentication of its own. Exposing its port to the internet exposes the instance.

Clip times: results/manifests/*.json, field elapsed_s, summarized by python3 results/summarize.py. Bake-off: results/manifests/20260711-131254-bakeoff_shaker.json, 1,490.4 s (Wan 2.2) plus 1,587.9 s (HunyuanVideo 1.5).

How it works

launch_rig.py creates an S3 bucket, an instance role and a security group with no inbound rules, then starts a g6e.xlarge from the AWS Deep Learning Base AMI. First boot installs ComfyUI and the FLUX.1-dev, Wan 2.2 A14B and HunyuanVideo 1.5 weights, binds ComfyUI to 127.0.0.1 and enables a watchdog timer. The workstation reaches ComfyUI through an SSM port forward.

run_job.py loads an API-format workflow per model, sets the prompt, seed, start image and frame count on nodes titled RIG_*, queues it, downloads the outputs and writes a manifest. run_chain.py builds longer clips from 5 s segments, each starting from the last frame of the one before. launch_rig.py and run_job.py accept --dry-run and print the AWS calls, HTTP requests and ffmpeg commands without running them; the chain and sync scripts have no dry-run mode.

flowchart LR
  launch[launch_rig.py] -- boto3 --> s3[(S3 bucket)]
  launch -- run_instances --> ec2[g6e.xlarge, no inbound rules]
  s3 -- bootstrap files --> ec2
  job[run_job.py] -- SSM port forward --> comfy[ComfyUI on 127.0.0.1:8188]
  ec2 --> comfy
  ec2 --> dog[idle_watchdog.sh every 5 min]
  comfy -- clips --> out[(outputs/run_id)]
  out -- s3_sync.py --> s3
  dog -- shutdown -h --> ec2

Watchdog limits: idle_stop_minutes = 30 and max_job_minutes = 360 in rig.config.toml; 3 h bootstrap limit and 600 s boot grace in bootstrap/idle_watchdog.sh; 180 minute fail-safe shutdown in the user data in launch_rig.py.

Measured results

16 runs were recorded on 2026-07-11. Two failed before queueing because ComfyUI was not reachable through the tunnel. Each model generated the same five clips from the same prompt and seed: one bake-off clip and four chained segments.

Source: results/manifests/*.json. Chart data: python3 results/summarize.py --check confirms docs/data.json matches the manifests. The manifests record no instance type or software versions; g6e.xlarge is inferred from rig.config.toml.

FLUX.1-dev stills took 16.7 s to 194.0 s. The two long runs were the first FLUX run of the day and the first after the video bake-off. That the difference is checkpoint loading is an inference; it was not measured.

Run it

  1. git clone https://github.com/Nysara-Global-LLC/comfyui-video-rig
cd comfyui-video-rig
  2. uv sync --group dev
uv run pytest -q
  3. uv run python launch_rig.py --dry-run launch
uv run python runner/run_job.py jobs/examples/shaker_demo.toml --dry-run

The dry runs need no AWS credentials. A real launch needs RIG_OUTPUTS_BUCKET set (see .env.example), the Session Manager plugin and a G instance vCPU quota of at least 4. The repository does not distribute model weights; each model has its own licence, listed in the README with its terms for generated outputs.

Limitations

  • ComfyUI, its custom nodes and torch are installed at their latest versions on first boot and are not pinned.
  • Jobs are submitted from the workstation; it must stay connected through the tunnel for the length of a run.
  • The prototype goal, a clip with a consistent presenter and a legible product label, has no recorded pass or fail.
  • The composited start frame workflow has no recorded run.
  • Errors carry forward through a chain: in the unpublished HunyuanVideo 1.5 run, the last frame of segment 2 shows a second headset that was not prompted, and later segments start from it.
  • Not measured: cost per clip, GPU memory use, model output quality.
